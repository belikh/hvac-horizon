# Feature matrix against the four competitors

Sources: VT = Versatile Thermostat, RM = RoomMind, CA = ClimateAdvisor, PID = smart_thermostat (ScratMan), ours = this integration's own feature, with no competitor.

Checked against commit db669c1. Code paths are under `custom_components/hvac_horizon/` unless a cell names `tests/`. HA tests are in `tests/ha/test_setup.py`. Unit tests are in `tests/test_*.py`, with the class name before the method where the test sits in a class.

Status values:
- `drives`: a call writes a device or a setpoint through the control path, or a value the control path reads changes that write (the cell says which). The cell cites the call site and the gates.
- `published`: a sensor or status attribute shows the value, and no control path reads it. The cell cites the sensor.py line.
- `control`: a gate, service, repair issue, persistent notification, event or user action. It acts without writing a device setpoint. The cell cites the call site and the test. `test: none` means no test covers it.
- `pure`: a function with no caller. `tests/test_no_dead_code.py` fails on it. No row carries this status.
- `missing`: not built. The cell states what is not built and cites nothing.

This file reflects the code on `main` at the time of the last update. Update it when a row changes.
